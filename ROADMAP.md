# LiteUtils ROADMAP

> Plain bash scripts that answer one V8 question about a hot path, BEFORE vs AFTER, with a fail-closed verdict.
> For a client who wants to run one script and read the answer, without wiring lite-leak / lite-gc-profiler /
> lite-perf-gate into a test suite.

Status: adopted 2026-11-02 (maintainer accepted every item below; the Phase 7 shape was adopted 2026-11-04 as D-4).
Baseline: `7f0ba7b initial commit` (one file, `inlining-budget-diff.sh`).

## 0. Scope

- This repo holds ONLY shell scripts plus their tests. No lite-leak, lite-gc-profiler or lite-perf-gate
  integration. Tests are `node:test` suites in the style of LiteSignal `test/94-inlining-budget-diff.test.mjs`.
- Each shipped script is ONE self-contained file a client can copy and run (`bash`, POSIX awk, `node`,
  optional `git`). Shared code exists only at authoring time (see S-2).
- The suite library packages stay the rigorous route; these scripts are the quick route and say so in
  their usage text.

## 1. Why this works (the template every script follows)

`inlining-budget-diff.sh` was adopted because of its skeleton, not because of inlining:

1. BEFORE vs AFTER on ONE node binary (driver mode, git-ref mode, frozen-file mode).
2. Normalize the trace (addresses, node ids, frequencies, timings), then compare as a MULTISET
   (`sort | uniq -c`, never `sort -u`): one site -> two sites is a DIFF.
3. Null control: runs 2..N of each side must match run 1, else NO-VERDICT.
4. Guard: a run with no evidence about the named function is NO-VERDICT, never "identical".
5. Fail closed: exit 0 SAME, 1 DIFF, 2 NO-VERDICT; any unplanned failure (rc 0 included) is 2, never 1.
6. A `--self-test` on canned trace text through the SAME awk programs, plus a node:test wrapper whose
   mutants (one exact edit of a copy) must turn the self-test red.
7. Verdict vs report: the verdict is gated; budget / tier / count tables are REPORTED and never move it.

A candidate script that cannot follow 1-5 (e.g. anything timed in ms) is a different product and does not
belong here.

## 2. Settled decisions (binding for every agent)

- S-1 Four new scripts, not nine. Ranking (build order): bytecode-budget, deopt-diff, allocation-diff,
  ic-diff. tiering-diff folds into deopt-diff; map/hidden-class diff folds into ic-diff; warmup-cost is
  dropped as a timing script; escape-analysis and ArrayBuffer-count are deferred (section 5).
- S-2 Shared code: authored once in `lib/*.sh` fragments (D-2, 2026-11-02: split into as many
  fragments as byte-identity needs -- six in Phase 1 (prologue, msdiff, common, args, modes,
  nullctl), plus v8limits, v8probe and stage in Phase 2; the count is not fixed -- so generated
  scripts stay byte-identical; a consuming package may either COPY a generated script or take
  LiteUtils as a devDependency);
  each shipped script is GENERATED by `build.sh`
  (expands `# @include lib/<file>.sh` marker lines in `src/<name>.sh` into `<name>.sh` at the repo root).
  The generated file is committed. A test fails when any shipped script differs from a fresh build.
  Shipped scripts never `source` anything at run time.
- S-3 What goes in lib: arg parsing helpers, `die` / `say` / `usage`, the fail-closed EXIT trap,
  `worst()`, `multiset()` + `MSDIFF_AWK`, the frozen-"before" refusal (`refuse_live` and helpers),
  `sha8`, `devino`, driver / ref / file mode plumbing, the null-control loop. Each script keeps its own
  normalizer awk, guard awk and report.
- S-4 Order of work: lock current behavior with tests BEFORE refactoring (Phase 0), then extract the lib
  (Phase 1) with the Phase 0 tests as the oracle; the regenerated `inlining-budget-diff.sh` must pass the
  same self-test and mutants unchanged.
- S-5 Tiers (suite verification tiers):
  - DETERMINISTIC (in `npm test`): every `--self-test`, every mutant row, the build-drift test, the
    bytecode-budget live check (S-6), and the `--allow-natives-syntax` control pairs (S-8).
  - STATISTICAL: real before/after comparisons of inlining / deopt / IC / allocation on a user driver
    (tier-up timing dependent). Never in `npm test`. Run under
    `node ~/.claude/hooks/quiet-lock.mjs run "LiteUtils <what>" -- <script> ...`.
  - REPORTED: every budget / tier / count table a script prints.
  - Statistical host: none. Statistical claims in this repo are REPORTED only.
- S-6 bytecode-budget is DETERMINISTIC: bytecode length does not depend on tier-up timing. It may gate
  (`--max fn=N`). Expectations record the node version; a run on a different node version is NO-VERDICT,
  never FAIL. A function never compiled (lazy) is NO-VERDICT.
- S-7 allocation-diff claims GC EVENT COUNTS only (young-generation collections inside a marked
  steady-state window), never bytes. Window must start after warm-up.
- S-8 Live controls: each script gets one must-DIFF and one must-SAME driver pair that use
  `--allow-natives-syntax` (`%PrepareFunctionForOptimization`, `%OptimizeFunctionOnNextCall`,
  `%NeverOptimizeFunction`) to force tier-up at a fixed point, so the pair is deterministic and runs in
  `npm test`. A control that is not reproducible over 20 local runs is moved out of `npm test` and
  recorded as STATISTICAL.
- S-9 Real-trace fixtures: alongside hand-written canned text, each self-test also runs on traces captured
  from node v26.8.2 (`test/fixtures/<script>/node-26.8.2/`), with the node version and capture command in a
  README beside them.
- S-10 ASCII-only sources and docs (U+00D7 and U+00B5 excepted). MIT (c) Zahary Shinikchiev.
- S-11 LiteSignal keeps a vendored copy of `inlining-budget-diff.sh`; LiteUtils is the source of truth.
  LiteSignal pins it by sha256 in a test (the maintainer coordinates the LiteSignal side).
- S-12 (maintainer 2026-11-02) LiteUtils is exempt from the torture.mjs law; gates = each script's
  --self-test (+ --fixtures), npm test, cmp frozen 7f0ba7b.

### Phase 2 -- bytecode-budget.sh (first new script) -- DONE 2026-11-02 (group 2b qa APPROVED)
- Extract `BYTECODE_AWK` + the `--print-bytecode` probe from inlining-budget-diff.
- Modes: report (lengths + every V8 limit crossed: 30 small, 75 heapnum, 460 TF single-inline,
  100 Maglev max, Maglev eager cutoff) and gate (`--max fn=N[,fn=N]`; exit 0 within, 1 over,

### Phase 7 -- rolling audit, per script, BEFORE Phase 6 (D-4, maintainer 2026-11-04; was "After Phase 6")
- Order: each script is audited as soon as it is AUDIT-READY, while the others are still being coded.
  Code only until 1.0.0: no adoption anywhere (consumers such as lite-signal audit the scripts; they do
  not gate on them). Then audit fixes -> Phase 6 docs -> a confirmation pass (every reproduction.mjs
  re-run on the release candidate) -> 1.0.0.
- AUDIT-READY <script> = every planned group for it DONE (engine review APPROVED; qa where its plan has
  one), no DEFERRED or LEAD fix for it without a DONE group (D-4a, D-4b), every RULED fix for it landed,
  no FAIL-OPEN for it open in NEXT.md "Open blockers / leads" or a PLAN CURRENT LEAD, npm test green,
  and committed by the maintainer. The burst that gets there writes `AUDIT-READY <script> <commit>
  <sha256/8 of the root script>` in NEXT.md; the orchestrator then pings the maintainer,
  who starts that script's audit.
- Auditors: the maintainer, lite-signal (the scripts it chose), the maintainer's reviewers, the
  orchestrator (triage), and one fresh agent reviewer per script with NO plan or review history (only
  the script, its tests, -h and real node runs). Once all five are through, one cross-script reviewer:
  flags, exit codes, refusal wording, header lines, the shared lib/ use.
- Format (the maintainer's practice): gitignored `audit/<YYYY-MM-DD>-<script>/FINDINGS.md` +
  `reproduction.mjs`, pinned in its header to the commit + sha256/8 audited. A chain, append-only:
  the first reviewer audits; each next one reads everything before it, CONFIRMS or REJECTS every
  finding (a rejection carries its own reproduction), and adds new findings. Every reviewer proposes a
  fix per finding or endorses an existing proposal. A proposal a reviewer denies STAYS in the file with
  the denial; nothing is deleted.
- Validation: every proposal is measured, not argued -- built as a candidate, then reproduction.mjs
  (the finding must show on the audited build and be gone on the candidate) + full npm test. The
  maintainer rules between the surviving proposals (Q-ids); the winner goes through the normal
  pipeline (coder -> reviewer), and its reproduction becomes a test row that fails on the audited
  build. Re-audit only what changed.
- Q-AUDIT-RUBRIC (maintainer 2026-11-07, addendum): "Rubric by consequence". Decide by what happens when it
  triggers, not how rare it is. (1) A finding that gives a
  wrong verdict is FIXED, unless the fix costs a new design: then refuse cheaply and document. (2) A finding
  that fails closed but is awkward is DOCUMENTED as a known limit. (3) A finding that needs a hostile setup
  is DOCUMENTED under "not a security boundary", and fixed only if a one-line refusal does it. Documented
  findings go to LEDGER section F and the README "Known limits" with their reproduction.
  The reviewer argues each finding's class; the maintainer rules the disputed ones.

### Post-1.0 research leads (maintainer 2026-11-03: "Yes, please, add them")
- These are LEADS, not plans. Each would start with a TASK 0 probe on the node of that day (a flag

- REPORTED probe facts (node v26.8.2, 2026-11-03, local darwin host, untimed,
  `env -u NODE_OPTIONS`, one run each):

  objects mixed in); `--trace-maglev-escape` and `--maglev-escape` are refused (`bad option`)
  because they are not flag names: `--v8-options` lists `--trace-maglev-escape-analysis` and
  `--maglev-escape-analysis`, both accepted (exit 0, output not probed). `--turbo-escape`,
  `--log-code`, `--log-maps`, `--log-maps-details` and `--trace-gc-object-stats` are listed; output
  not probed.
- L1 import-audit.sh (top pick): what importing a module does to everyone else -- globals changed,
  open timers / handles, import-time allocation, V8 protector cells invalidated. Checks the
  `sideEffects: false` law; expected DETERMINISTIC except import-time allocation, which reuses
  allocation-diff machinery and so is STATISTICAL, REPORTED only (S-5); light on V8 internals.
- L2 shape-diff.sh: per-site elements-kind and field-representation stability, dictionary-mode
  objects (`--trace-elements-transitions`, `--trace-generalization`; `--log-maps` is already
  ic-diff's opt-in map section, S-1 / Phase 5). Hard part is attribution (`<unknown>:<unknown>`,
  node-internal noise; likely the ic-diff pc -> code-creation join).
- L3 optimization-ablation mode for deopt-diff / allocation-diff (not a new script): run with one
  optimization off (`--no-turbo-escape`, inlining off); indirect answer to the deferred
  escape-analysis item. Probe that the `--no-` forms are accepted.
- L4 optimized-code size diff: machine-code size per function per tier from `--log-code` records;
  catches inlining bloat that bytecode-budget cannot see; reuses ic-diff's code-creation parser.
- L5 heap object counts by constructor, before vs after: the bytes / retention gap allocation-diff
  leaves (S-7: counts, not bytes). Check overlap with lite-leak first.
- L6 suite-wide runner (not a tool): run the five scripts over every package's drivers; store the
  REPORTED tables as a per-package baseline.
